# 03 — Data Sources

Every source the platform uses: access method, exact locations, schedule, cost, risk, and failure modes. All pipelines that consume these are specified in `05-pipelines.md`.

## 1. Free bulk market data

### 1.1 Redfin Data Center (primary market-metrics source)
- **What**: MLS-derived market tracker by property type — median sale price, median new-listing price, median $/sqft, homes sold, inventory, active listings, new listings, pending sales, median DOM, **average sale-to-list ratio**, share sold above original list, months of supply, % off market in two weeks. Geo levels down to ZIP and neighborhood.
- **Access**: direct HTTPS GET of plain CSVs from a public S3 bucket (bucket is not listable — construct exact keys):
  - `https://redfin-public-data.s3.us-west-2.amazonaws.com/redfin_data_center/property_types/monthly/all_zips.csv`
  - same pattern for `all_cities`, `all_counties`, `all_metros`, `all_states`, `all_neighborhoods`
  - The earlier `redfin_market_tracker/*.tsv000.gz` objects still exist but stopped updating on 2026-06-02 (final window Mar–May 2026); Redfin's site kept publishing, at this new location and in this new format.
- **Format**: quoted headers with spaces and units (`"MEDIAN SALE PRICE NSA ($)"`, `"AVERAGE SALE TO LIST RATIO (%)"`), `NA` for null, `IS SEASONALLY ADJUSTED` true/false. `REGION NAME` is the bare ZIP (`94402`, leading zeros preserved), `San Mateo, CA`, or `San Mateo County, CA`; `REGION ID` is Redfin's key and a name can cover a namesake elsewhere in the state (`Mountain View, CA` is two ids) — keep, per name, the id with the most closed sales over the history.
- **Size**: uncompressed — `all_zips` 2.9 GB, `all_cities` 2.2 GB, `all_counties` 0.4 GB → parse with DuckDB (`all_varchar`, so ZIP names are never sniffed as integers) and filter to the geography's ZIPs / cities / counties (`settings.geo`; county names must match Redfin's region names minus `, <ST>`) before loading SQLite. `redfin-market` HEADs the objects first and compares ETag/Last-Modified/size (plus the target ZIP/city lists) with the last run, so unchanged days cost no download.
- **Update cadence**: roughly weekly (Redfin's tracker page says Thursdays; the objects have also landed on Mondays). Pipeline still runs daily with the signature no-op (05 §1). **History is restated on every release** (overlapping months move by a few %) → truncate-and-replace all `source='redfin'` rows per geo level, never diff/append.
- **Terms**: free, explicitly published for reuse with citation ("Data from Redfin, a national real estate brokerage").
- **Failure modes**: schema/column renames (fail loudly listing missing columns); an unknown `FREQUENCY` value (fail loudly — the window semantics would be unknown); a level whose region names no longer match any target (item failure, level left untouched); ZIP-level rows are 3-month rolling windows and noisy in thin markets (smooth in `build-index`, note in UI).
- **Columns (verified September 2026)**: ZIP and city files publish `MONTHS OF SUPPLY` directly (≈ `3 × INVENTORY / HOMES SOLD`, rounded to 0.1), so `months_supply` is ingested at every level. There is no price-drops column at any level, so `pct_price_drops` does not exist in `market_metrics`. Ratio columns are percent and are stored ÷100 (`avg_sp_lp` 1.094, `pct_sold_above_list` 0.78). `MEDIAN NEW LISTING PRICE ($)` feeds `median_list_price`; `SHARE SOLD ABOVE ORIGINAL LIST (%)` feeds `pct_sold_above_list`. `MOM`/`YOY` columns are ignored.
- **Window arithmetic**: ZIP and city rows are `FREQUENCY='Rolling 3 Months'` (`period_begin`/`period_end` span 88–91 days, e.g. `2026-06-01` → `2026-08-31`), stored as `period='3m'`, so their `homes_sold` is a **3-month total**, not monthly. Any rate computed from them must divide by 3. County rows are `Monthly` → `period='monthly'`. `period_start` in `market_metrics` stores the window *start*, so the ZIP/city series look ~2 months staler than they are.

### 1.2 Zillow Research (price index source)
- **What**: ZHVI (smoothed home-value index; ZIP + neighborhood levels; SFH cut available), ZORI (rent index), inventory/list-price series.
- **Access**: direct CSV URLs (the landing page `zillow.com/research/data` 403s non-browser agents; the CSV endpoints work). Verified July 2026, stored in config (env-overridable — they drift): ZHVI SFH `.../zhvi/Zip_zhvi_uc_sfr_tier_0.33_0.67_sm_sa_month.csv` (+City variant); ZORI `.../zori/Zip_zori_uc_sfrcondomfr_sm_month.csv`. **Note: ZORI has no single-family-only ZIP cut — sfrcondomfr (all home types) is the finest published.**
- **Update cadence**: monthly, ~16th. **The entire history is restated each release → truncate-and-replace all Zillow-sourced rows, never diff/append.**
- **Terms**: free with attribution.
- **Failure modes**: URL drift (fail loudly, keep last good data — the cached copy in `data/raw/` remains authoritative until a fresh download succeeds); ZIP coverage gaps for thin markets (fall back city → county in `build-index`).

### 1.3 FRED (rates + macro)
- **What/series**: `MORTGAGE30US`, `MORTGAGE15US` (weekly Freddie Mac survey rates), the metro Case-Shiller index named by `[market].case_shiller_fred_id` in the geography file (e.g. `SFXRSA` for San Francisco, monthly; stored as series `CASESHILLER`).
- **Access**: REST API, free key (`FRED_API_KEY`): `https://api.stlouisfed.org/fred/series/observations?series_id=...&api_key=...&file_type=json`.
- **Failure modes**: none notable; generous rate limits.

### 1.4 Other free public sources
- **Hazard layers** (one-time static fetches, declared per state pack as `HazardLayer` records — `docs/packs/README.md`): FEMA NFHL flood zones for every geography; the `ca` pack adds CAL FIRE Fire Hazard Severity Zones and CGS liquefaction + Alquist-Priolo fault zones. `hb pipeline hazards-fetch` downloads each layer as GeoJSON scoped to the geography (`data/raw/hazards/{key}.geojson`, 05 §16); point-in-polygon with `shapely` via `hb pipeline hazards`. Working ArcGIS REST query endpoints (verified 2026-07, all public, paged `f=geojson`):
  - FEMA NFHL layer 28 `hazards.fema.gov/arcgis/rest/services/public/NFHL/MapServer/28/query` filtered `DFIRM_ID IN (<state fips><county fips>C, …)` from the geography's counties (`06081C`, `06085C` for San Mateo + Santa Clara) + SFHA/0.2%-subtype → `zone_value = FLD_ZONE` (+ subtype);
  - CAL FIRE `services1.arcgis.com/jUJYIo9tSA7EHvfZ/…/fhsz24_1/FeatureServer/0` (2024 combined SRA/LRA — the official combined service is token-gated), envelope-filtered by the geography's `[market].hazard_bbox` → `FHSZ_6Class`;
  - CGS AGOL layers `services2.arcgis.com/zr3KAIbsRSUyARHG/…/CGS_Liquefaction_Zones` and `…/CGS_Alquist_Priolo_Fault_Zones` (the state `gis.conservation.ca.gov` server is unreliable), same envelope → `QUAD_NAME`, presence-based.
- **Census reference files for `hb setup`** (`backend/hb/setup_geo.py`): the places and ZCTA Gazetteers (`www2.census.gov/geo/docs/maps-data/data/gazetteer/{year}_Gazetteer/{year}_Gaz_{place|zcta}_national.zip` — city names and centre points, ZIP centre points for the map zoom and hazard bbox), the 2020 ZCTA↔place and ZCTA↔county relationship files (`.../geo/docs/maps-data/data/rel2020/zcta520/tab20_zcta520_{place|county}20_natl.txt` — which ZIPs make up each city by share of the ZIP's land, and each city's county name + FIPS), and the ACS 5-year tables B25090 (aggregate real-estate taxes paid) / B25082 (aggregate value) from the table-based summary file (`.../programs-surveys/acs/summary_file/{year}/table-based-SF/data/5YRData/acsdt5y{year}-{b25090|b25082}.dat`) for each county's effective tax rate. Plain HTTPS downloads, no key, cached in `data/raw/` on first use; a `{year}` template is tried newest year first so a new release is picked up without a code change. Fetched only when the wizard runs, never by a scheduled job. Free.
- **Census geocoder** (`geocoding.geo.census.gov/geocoder/locations/onelineaddress`, `benchmark=Public_AR_Current`, `format=json`; `backend/hb/open_houses/geocode.py`): resolves the home address to the Open Houses distance / route origin (`settings` key `home_location`) — called from the Open Houses API when the origin is seeded from `HOME_ADDRESS` or edited on the page, not by any job. US addresses only; free, no key. The `Geocoder` Protocol (`GEOCODER`) lets another market swap in its own.
- **NCES schools + district polygons** (ArcGIS REST on `services1.arcgis.com/Ua5sjt3LWTPigjyD/arcgis/rest/services/`; `pipelines/schools.py`, `pipelines/school_districts.py`): the CCD "School_Characteristics_Current" point layer (`/FeatureServer/1/query`, pages of 2000) is the public-school directory for the geography's state, and the TIGER "School_Districts_Current" polygon layer (`/FeatureServer/0/query`, pages of 500; ~940 districts for California) gives the boundaries houses are assigned by (05 §9, §12). Both jobs are in `DAILY_SEQUENCE` and no-op on an unchanged content hash; the layers change about annually. Free, no key. Empty attributes arrive as a single space — `.strip()` before truthiness checks.
- **CAASPP research files** (`caaspp-elpac.ets.org/caaspp/researchfiles/sb_ca{year}_all_csv_v1.zip` + `sb_ca{year}entities_csv.zip`, year from `CAASPP_YEAR`; `pipelines/school_ratings.py`): California's Smarter Balanced results (% met/exceeded standard, ELA + Math, all students, all grades), from which `school-ratings` derives a statewide decile per school → `schools.rating` + `school_rating_snapshots(source='caaspp')` (05 §10). Standalone job (annual data, ~157 MB), not in `DAILY_SEQUENCE`; a no-op outside California. Free, no key.
- **Google Maps directions links** (`https://www.google.com/maps/dir/?api=1&origin=…&destination=…&waypoints=…&travelmode=driving`; `backend/hb/open_houses/route.py`): the open-house day planner hands the buyer a multi-stop driving route URL (the last stop as destination, the rest as `|`-joined waypoints, at most `MAPS_MAX_STOPS` = 10 stops). Outbound link only — nothing is fetched from Google. Free.

## 2. Listings (the daily scrape)

### 2.1 HomeHarvest (PyPI `homeharvest`) — primary listing source
- **What**: Python library riding Realtor.com's internal GraphQL API. Functions return pandas DataFrames. `scrape_property(location="Sunnyvale, CA", listing_type="for_sale"|"pending"|"sold", past_days=N, property_type=["single_family"])`.
- **Fields available** (verified live against v0.8.18, July 2026): `property_id` (stable per home), `listing_id` (per marketing episode — our `source_listing_id`), `mls_id`, `status` (FOR_SALE/PENDING/SOLD) + `mls_status`, `full_street_line`/`street`/`unit`/`city`/`state`/`zip_code`, `latitude`/`longitude`, `beds`/`full_baths`/`half_baths`/`sqft`/`lot_sqft`/`year_built`, `list_price`/`list_date`, `sold_price`/`last_sold_date`/`last_sold_price`, `pending_date`, `days_on_mls`, `primary_photo`/`alt_photos`, `property_url`, `price_per_sqft`, `hoa_fee`, `estimated_value` (Realtor.com AVM), and the listing side flattened from Realtor's `advertisers` block — `agent_name`/`agent_email`/`agent_phones` (list of `{number, type, primary, ext}`; `type` labels are inconsistent: `Mobile`, `Cell`, `BUSINESS_MOBILE`, `Office`, `Fax`, `tfn`…), `agent_mls_set`, `agent_nrds_id`, `office_name`/`office_email`/`office_phones`, `broker_name`, `builder_name`, `mls`. The advertiser block is absent on roughly one listing in four.
- **Status**: ~710 GitHub stars, actively maintained (v0.8.x, Dec 2025). Realtor.com's anti-bot stack is hostile to DIY scraping but HomeHarvest tracks the internal API.
- **Etiquette**: library batches internally; still run city-by-city with 2–5 s jittered sleeps between cities.
- **Failure modes**: breaking changes on Realtor.com's side → pin the version, catch per-city, alert self on 2 consecutive failed `listing-scan` runs (09 §2). Occasional missing sqft/lat/lon → entity resolution tolerates nulls (05 §5).

### 2.2 Realtor.com frontdoor GraphQL — estimate, details, gallery, price history
- **What**: the internal endpoint HomeHarvest itself rides (`https://www.realtor.com/frontdoor/graphql`, POSTed with HomeHarvest's browser `DEFAULT_HEADERS`, no auth token), called directly for the data HomeHarvest drops: the **Realtor.com home-value estimate** (`avm_snapshots.source='realtor_estimate'`), below-the-fold details to NULL-fill `properties`, the full photo gallery, and the `property_history` timeline (`properties.price_history`). The shared plumbing is `pipelines/realtor_gql.py` (address → `mpr_id` via the search-suggestions query; the id the scan stored in `source_ids` is preferred, so an enrichment costs one call); the consumers are `enrich.py` (05 §7) and `price_history.py` (05 §14).
- **Use**: per-property enrichment (tracked/shortlisted homes only) and the price-history backfill, NOT bulk scanning. ~1 req/sec, jittered; `price-history` runs in resumable `--limit` chunks.
- **Failure modes**: query-shape drift on Realtor's side. Wrap every call; on failure, record an `avm_snapshots` miss and continue. Redfin's "Stingray" property API is not an alternative for any of this: it sits behind AWS WAF and answers every non-browser request with 403.

### 2.3 Redfin map-search (GIS) — open houses
- **What**: Redfin's `https://www.redfin.com/stingray/api/gis` search, polygon-filtered (`poly` = the city's bbox from the stored active homes), active single-family only (`status=1`, `uipt=1`, `num_homes=350`, plus the paging/sort/sale-type params Redfin's own map sends — without them `poly` is ignored). Returns each home's NEXT open-house slot (epoch ms, UTC) and no event link; a box that hits the 350-home cap is split into quadrants, up to 4 levels deep. Redfin carries open houses Realtor's feed often lacks, so it runs alongside the Realtor source; its listing ids are its own, so each slot carries the MLS number + ZIP and `open-houses` matches it to the listing the scan stored (05 §4c). Source `redfin` in `backend/hb/open_houses/sources/redfin.py`, enabled by `OPEN_HOUSE_SOURCES` (default `realtor,redfin`).
- **Access**: Redfin answers plain HTTP clients with 403, so requests go through `curl_cffi` with Chrome impersonation; one request per city or quadrant, with a 2–5 s random sleep before each.
- **Schedule**: in the tail of every `listing-scan`, and on `hb pipeline open-houses`. Free, no key.
- **Failure modes**: a `resultCode` other than 0 raises (a per-source item error — the Realtor source still runs); the `{}&&` prefix Redfin puts on the body is stripped before parsing.

## 3. Paid / freemium APIs

### 3.1 RentCast API — per-property AVM + comps (the paid core)
- **What**: property records (characteristics, tax history), **value estimate AVM with the comps used returned in the same response**, rent AVM, active listings, ZIP market stats.
- **Auth**: `X-Api-Key` header (`RENTCAST_API_KEY`). Base `https://api.rentcast.io/v1/`. The only endpoint called is `/avm/value?address=...` (`enrich.py` `fetch_rentcast_avm`): the value estimate plus the comps it was built from, persisted as `avm_snapshots(source='rentcast')` and `sales(source='rentcast')`.
- **Pricing**: **Developer tier free, 50 requests/mo** → Foundation **$74/mo, 1,000 req**. Plan: free tier (user-triggered enrichment only); upgrade during an active hunt, cancel after closing.
- **Budget guard**: `rentcast_budget` counter in DB; refuse calls beyond `RENTCAST_MONTHLY_LIMIT` (default 45 on free tier) and surface remaining quota in the UI.
- **Caveat**: its "tax assessed value" fields are Prop 13 basis — meaningless for market value; use only the AVM fields.

### 3.2 RapidAPI Zillow wrappers (optional, off by default)
- Scraped-Zillow resellers (e.g. `zillow-com1`) providing Zestimate/price history; ~$10–30/mo tiers. **Breakage-prone and ToS-gray — implement behind a feature flag (`ZILLOW_WRAPPER_ENABLED=false`), treat as supplemental AVM only.** The AVM spread works fine with own CMA + Realtor.com estimate + RentCast.

### 3.3 Explicitly skipped
ATTOM (enterprise sales process), MLS/IDX feeds (licensing unavailable to consumers — this is why no public listings API exists), Datafiniti, Ownerly, ZTRAX (discontinued 2023).

### 3.4 SchoolDigger API v2.4 — statewide school rankings (optional, free developer plan)
- **What**: the statewide ranking of every public school in the geography's state (`rankStatewidePercentage` = "ranks above X% of the state's schools", normalized onto the 1–10 badge scale), an independent rating source next to the CAASPP decile in California → `school_rating_snapshots(source='schooldigger')` (05 §13). Matching is by NCES school id (SchoolDigger's ids are NCES ids), with a (zip, normalized name) fallback.
- **Auth**: `appID` + `appKey` query params (`SCHOOLDIGGER_APP_ID` / `SCHOOLDIGGER_APP_KEY`, free developer plan at developer.schooldigger.com). Endpoint `https://api.schooldigger.com/v2.4/schools`; it has no county filter and silently ignores unknown params, so the job queries district by district.
- **Budget**: the free plan allows **20 calls/day** (`x-dayrate-limit` headers). `schooldigger-ratings` is in `DAILY_SEQUENCE` and converges across runs rather than finishing in one: only the districts assigned to properties in the DB (~20, 1–3 calls each), per-district progress in the `settings` key `schooldigger_progress`, a day-scoped guard (`schooldigger_budget`, ceiling `SCHOOLDIGGER_DAILY_LIMIT`, default 18), a clean stop when the API answers 429, and a no-op while every rated district is fresh. Missing credentials ⇒ no-op, never a failure. Do not spend the quota on ad-hoc calls.

### 3.5 Pushover — phone push for alerts
- **What**: the `pushover` delivery channel (`backend/hb/alerts/channels.py`, 09 §4): one POST to `https://api.pushover.net/1/messages.json` per alert (`token`, `user`, title = the alert type, the rendered message, the listing page under `APP_BASE_URL` as the tap-through URL). Not a data source — nothing is read back.
- **Auth**: `PUSHOVER_TOKEN` (application token) + `PUSHOVER_USER` (user key), both from the Pushover dashboard. An application token can only send to its own user key, so a leaked pair lets someone page you and nothing more; regenerate it on the dashboard.
- **Schedule**: fires from `hb alerts send` (hourly at :30 on the installed schedule) whenever `pushover` is in `ALERT_CHANNELS`. Nothing metered in the app. Missing credentials, a non-200 or `status != 1` response, or an unreachable host all count as a failed channel; the alert is retried next run unless another channel (`log`) already delivered it.

## 5. Scraping etiquette & legality posture (binding rules)

Context (2025–2026): scraping public pages is not a CFAA violation (*Van Buren* 2021, *hiQ v. LinkedIn* 9th Cir.); browsewrap ToS generally don't bind logged-out visitors (*Meta v. Bright Data*, N.D. Cal. 2024); there is no documented enforcement against low-volume personal users — the realistic worst case is an IP ban. The risk with teeth is **copyright in listing photos**. Therefore, hard rules:

1. **Logged out always.** Never create or use an account for any scraping path (contract liability attaches to accounts).
2. **~1 request/second with jitter** per host; run scans sequentially, not in parallel, per source. The one exception is listing photos: they come from the image CDN (`*.rdcpix.com`), not the site's pages, and are fetched `PHOTO_WORKERS` (4) at a time with the same per-connection pause — what a browser does to show one gallery — and a 429/503 pauses every worker (05 §4.6).
3. **Cache aggressively**: every raw download stored under `data/raw/<source>/<date>/` with a `.sha256` sidecar; never re-fetch what the content hash says is unchanged.
4. **Photos: download once for personal reference, never republish.** Listing images are downloaded to `data/photos/<property_id>/` (see `05-pipelines.md` §4.6) at scrape/enrich time and served only by the local API. Photos are copyrighted (photographer/MLS) — they must never be redistributed, posted publicly, or included in any deployed instance that is not access-protected. Each file is fetched at most once (existence check ⇒ skip), at the same ~1 req/s pace.
5. **Personal use only**: no public deployment of scraped data or photos, no redistribution, no resale.
6. Respect failures: a 429/503 from the photo CDN pauses every worker (`_Throttle`: `PHOTO_BACKOFF_S` 5 s, doubling to a 60 s cap, reset by the next success) and the file is retried up to `PHOTO_RETRIES` (3) times; a dropped or timed-out connection or another 5xx is one request's bad luck, retried by that worker alone (`PHOTO_RETRY_PAUSE_S` 2 s, doubling per attempt); a 4xx other than 403/429 means the file is gone and is not retried. A 403 is how the CDN's rate limit answers: a lone one is skipped, `PHOTO_BLOCK_AFTER` (8) in a row pause every worker `PHOTO_BLOCK_PAUSE_S` (60 s, doubling), and when they persist through `PHOTO_BLOCK_ROUNDS` (3) pauses the photo tail stops for the run rather than keep hitting a CDN that is refusing us; the next scan picks the files up (`pipelines/listing_scan.py` `_Throttle`, `_fetch_one`). Everything else is per item. Never rotate proxies or spoof beyond a normal browser User-Agent; the Redfin open-house source's `curl_cffi` Chrome impersonation (§2.3) is the one place a browser fingerprint is presented.
